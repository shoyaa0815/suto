Phase 0 - AI Harness Foundation                         [DONE]
============================================================
เป้าหมาย: มี runtime กลางที่ AI เรียก tools ได้และควบคุมสิทธิ์ตาม mode

- chat และ agent mode
- tool registry และ tool schema
- tool-calling loop พร้อมจำกัดจำนวนรอบ
- progress แสดงงานปัจจุบัน เวลาที่ใช้ และ token
- developer timing log
- CLI พร้อม /help, /exit และ /quit
- web, datetime และ attached-file tools
- test พื้นฐานของ runtime และ tools


Phase 1 - Persistent Automation Jobs                    [DONE]
============================================================
เป้าหมาย: สั่งงานเบื้องหลังได้ และงานไม่หายเมื่อปิดโปรแกรม

- SQLite job store
- สถานะ queued, running, completed, failed และ cancelled
- background worker แบบทำทีละงาน
- เก็บผลลัพธ์ error เวลา และจำนวน token
- เก็บ progress events
- กู้สถานะงานที่โปรแกรมถูกปิดระหว่างทำ
- CLI: /run, /jobs, /status และ /cancel

หมายเหตุ: Phase นี้ commit แล้วใน e543ac3


Phase 2A - Restricted Workspace Read                    [DONE]
============================================================
เป้าหมาย: ให้ agent อ่าน project ที่ user เลือกได้อย่างปลอดภัย

- /run --workspace <path> <task>
- workspace แยกตาม job
- list_workspace_files
- read_workspace_file
- search_workspace
- ป้องกัน ../ path traversal
- ป้องกัน symlink ที่ชี้ออกนอก workspace
- จำกัดจำนวนไฟล์ ขนาดไฟล์ และผลการค้นหา
- บันทึก tool audit ต่อ job
- /status แสดง tool ล่าสุด


Phase 2B - Opt-in Workspace Write                       [DONE]
============================================================
เป้าหมาย: ให้ agent แก้ไฟล์ได้เฉพาะ job ที่ user อนุญาต

- /run --workspace <path> --allow-write <task>
- ค่าเริ่มต้นของทุก job ยังเป็น read-only
- apply_workspace_patch สำหรับสร้างหรือแทนที่ text file
- ต้องอ่านไฟล์เดิมและส่ง expected SHA-256 ก่อนแก้
- ปฏิเสธการเขียนเมื่อไฟล์เปลี่ยนหลังจากที่ agent อ่าน
- เขียนไฟล์แบบ atomic replace
- รักษา permission เดิมของไฟล์
- จำกัดขนาดเนื้อหาและ diff
- ห้ามเขียนออกนอก workspace ผ่าน path หรือ symlink
- บันทึก path, unified diff และ hash ก่อน/หลังลง SQLite
- /changes <job_id> สำหรับดูสิ่งที่ job แก้
- tool audit ไม่เก็บเนื้อหาไฟล์เต็ม
- ยังไม่อนุญาตลบไฟล์หรือรัน command

Phase 3 - Safe Command Execution                        [PENDING] <- NEXT
============================================================
เป้าหมาย: ให้ automation รัน test, formatter และคำสั่งที่จำเป็นได้

- เพิ่มสิทธิ์แบบ opt-in เช่น --allow-shell
- ค่าเริ่มต้นต้องห้ามรัน command
- command ทำงานได้เฉพาะใน workspace
- กำหนด allowlist/denylist ของ executable และ argument อันตราย
- block shell expansion, command chaining และ path escape
- timeout ทุก process
- จำกัด stdout/stderr และขนาด log
- ยกเลิก process tree เมื่อ /cancel หรือ timeout
- เก็บ command, exit code, เวลา และ output summary ใน audit
- แสดง command ล่าสุดใน /status
- เพิ่ม /logs <job_id> สำหรับดู execution log
- test การ escape workspace, timeout, cancellation และ output limit

Definition of done:
agent แก้ไฟล์แล้วรัน test เพื่อตรวจงานได้ โดยต้องได้รับสิทธิ์จาก user


Phase 4 - Plan, Verify and Recovery                      [PENDING]
============================================================
เป้าหมาย: ทำงานหลายขั้นได้เสถียร ไม่วนลูปและรู้ว่างานสำเร็จจริง

- สร้าง task plan ก่อนลงมือ
- เก็บ step และสถานะของแต่ละ step ใน SQLite
- checkpoint หลังแต่ละขั้น
- verify หลังแก้ไฟล์ เช่น test หรือ validation command
- จำกัดรอบ tool, เวลา, token และจำนวนไฟล์ที่เปลี่ยนต่อ job
- ตรวจจับ tool loop หรือการทำ action เดิมซ้ำ
- retry เฉพาะ error ที่ retry ได้ พร้อม backoff
- resume งานจาก checkpoint ที่ปลอดภัย
- สรุปว่าแก้อะไร ตรวจอะไร และอะไรยังไม่สำเร็จ
- เพิ่ม /plan <job_id> และแสดง blocked reason ใน /status

Definition of done:
job แบบหลายขั้นหยุดอย่างมีเหตุผล ตรวจผลได้ และไม่ claim success ถ้า verify ไม่ผ่าน


Phase 5 - Approval and Change Control                    [PENDING]
============================================================
เป้าหมาย: ให้งานที่เสี่ยงต้องรอ user อนุมัติก่อนดำเนินการ

- policy แยก read, write, command และ destructive action
- approval request ที่ persistent ใน SQLite
- job เปลี่ยนเป็น waiting_approval โดยไม่ถือ worker ค้าง
- /approve <job_id> และ /reject <job_id>
- preview command หรือ diff ก่อนขออนุมัติ
- จำกัดอายุ approval และผูก approval กับ action ที่แน่นอน
- ห้ามใช้ approval เก่ากับ command/diff ที่เปลี่ยนไป
- secret redaction ใน prompt, log, error และ audit
- audit trail ว่าใครอนุมัติอะไรและเมื่อไร

Definition of done:
action เสี่ยงไม่สามารถเกิดขึ้นได้โดยไม่มี approval ที่ตรงกับ action นั้น


Phase 6 - Scheduler and Triggers                         [PENDING]
============================================================
เป้าหมาย: เปลี่ยนจากสั่งงานเองเป็น automation ที่ทำงานตามเวลา/เหตุการณ์

- ตาราง schedules และ trigger history ใน SQLite
- one-time schedule
- interval และ cron schedule พร้อม timezone
- เปิด/ปิด schedule
- ป้องกัน schedule เดียวรันซ้อนกัน
- idempotency key ป้องกัน event ซ้ำ
- retry policy และ missed-run policy
- CLI: /schedule, /schedules, /pause และ /resume
- สร้าง job ใหม่จาก schedule โดยใช้ permission profile ที่บันทึกไว้
- เก็บประวัติว่า trigger ไหนสร้าง job ไหน

Definition of done:
ปิดแล้วเปิดโปรแกรมใหม่ schedule ยังอยู่ และไม่สร้างงานซ้ำโดยไม่ตั้งใจ


Phase 7 - Reusable Automations and Skills                [PENDING]
============================================================
เป้าหมาย: เก็บ workflow ที่ใช้ซ้ำได้แทนการเขียน prompt ใหม่ทุกครั้ง

- automation definition: ชื่อ, prompt template, workspace และ policy
- parameter schema สำหรับ input ของแต่ละ automation
- reusable skills/instructions ที่โหลดเฉพาะงาน
- version ของ automation และ skill
- validate configuration ก่อนเริ่ม job
- CLI สำหรับสร้าง ดู แก้ และรัน automation ที่บันทึกไว้
- export/import definition โดยไม่รวม secret
- run history แยกตาม automation

Definition of done:
user เรียก workflow เดิมด้วย input ใหม่ได้ โดย permission และขั้นตอนยังเหมือนเดิม


Phase 8 - Observability and Production Hardening         [PENDING]
============================================================
เป้าหมาย: ใช้งานระยะยาวได้ ตรวจปัญหาและควบคุมทรัพยากรได้

- structured logs พร้อม job_id และ event_id
- metrics: queue time, run time, success rate, token และ tool errors
- retention/cleanup policy สำหรับ events, diffs และ logs
- database backup และ migration version
- graceful shutdown โดยไม่ทำข้อมูลงานเสีย
- worker lock ป้องกันหลาย process หยิบ job เดียวกัน
- concurrency limit แยกตาม workspace
- rate limit และ resource quota
- health check และ diagnostics command
- integration tests ครบตั้งแต่ submit จนจบ job

Definition of done:
ระบบรันต่อเนื่องได้ มีข้อมูลพอวิเคราะห์ failure และ upgrade database ได้ปลอดภัย

เป้าหมาย: เพิ่มความสามารถหลัง automation core เสถียรแล้ว

กติกาหลักของทุก Phase
======================
- default deny: capability ใหม่ต้องปิดไว้ก่อน
- permission ต้องผูกกับแต่ละ job
- จำกัด path, เวลา, token, output และจำนวน action
- action ที่เปลี่ยน state ต้องมี audit
- cancellation ต้องหยุดงานจริง ไม่ใช่เปลี่ยนแค่สถานะ
- agent ต้อง verify ก่อนรายงานว่าสำเร็จ
- migration ต้องรองรับฐานข้อมูลเดิม
- ทุก feature สำคัญต้องมี test ก่อนถือว่า DONE
